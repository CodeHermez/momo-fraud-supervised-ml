# momo-fraud-supervised-ml

Risk-based cost-sensitive fraud detection on mobile money transactions, supporting _Financial Fraud Detection in Mobile Money Networks Using Supervised Machine Learning_ (COS700).

Evaluation is **unitless throughout**: a severity ratio and a 0–100 risk score, never a currency.

This README has two halves. **[Reproducing the study](#reproducing-the-study)** is the step-by-step guide for someone who has just cloned the repository and wants the prototype running and the experiments re-run. **[The study](#the-study)** summarises what was asked and what was found.

## Reproducing the study

### What you get from a clone, and what you have to rebuild

Everything needed to *check* the results is committed. Everything derived from the raw dataset is not, because the dataset is ~470 MB and the probability cache built from it is another ~210 MB.

| Path | In the clone? | What it is | How to get it |
| --- | --- | --- | --- |
| `src/momo_fraud/` | yes | the analysis library: metrics, splits, risk, experiment protocol, guards | — |
| `notebooks/00`–`10` | yes | orchestration; each writes into `results/` and `figures/` | — |
| `scripts/` | yes | `repairs/`, `freeze/`, `experiments/` (E2, E3, E4, E6), `report/` table builders | — |
| `results/` | yes | every result file, with provenance and a VALID / SUPERSEDED / DIAGNOSTIC status in `results/experiment_index.json` | regenerated by the steps below |
| `results/E2_cells/`, `E3_cells/`, `E6_cells/` | yes | one JSON per experiment cell (the runners resume from these) | — |
| `figures/` | yes | the figures, PNG and vector PDF | regenerated by the steps below |
| `artifacts/` | yes | the frozen model bundle the prototype loads (`model.json` + preprocessor + thresholds + model card) | rewritten by notebook 08 |
| `evidence/audit_and_experiment_summary.pdf` | yes | condensed record of the audit, the freeze and the four experiments | — |
| `prototype/` | yes | the Streamlit demo, its tests and a 200-row sample CSV | — |
| `data/raw/PS_20174392719_1491204439457_log.csv` | **no** | PaySim, 6,362,620 rows | [Step 2](#step-2--get-the-dataset) |
| `data/processed/paysim.parquet` | **no** | a parquet cache of the CSV | written automatically on first load |
| `predictions/` | **no** | cached validation/test probability vectors (~1,000 parquet files) | notebooks 03–05 and 10, and the E2/E3 runners |
| `prototype/data/demo_sample.parquet` | **no** | labelled test-set slice for the prototype's explorer page | `prototype/scripts/build_demo_sample.py` |
| `report/`, `docs/` | **no** | the LaTeX report and the long-form Markdown reports | not distributed; see `evidence/` for the condensed record |

So there are four levels of reproduction, each building on the last:

| Level | Needs the dataset? | What it gives you |
| --- | --- | --- |
| [1. Verify](#level-1--verify-without-the-dataset) | no | tests pass, the frozen baseline's 9 consistency checks pass, E4 and E6 re-aggregate from the committed cells and pass QC, the E6 figure and the report tables regenerate |
| [2. Prototype](#level-2--run-the-prototype) | partly | the Streamlit demo with all seven pages working, locally or in Docker |
| [3. Notebooks](#level-3--re-run-the-notebooks-and-repairs) | yes | every `results/0*`–`10*` file and its figure, re-derived from the raw data |
| [4. Experiments](#level-4--re-run-the-experiments-e3-e2-e4-e6) | yes | E2, E3, E4 and E6 refitted and re-evaluated from scratch |

### Step 0 — Prerequisites

- **Python 3.14** (3.14.4 is what produced the committed results; `pyproject.toml` allows ≥ 3.12, and every pin in `requirements.txt` is verified to resolve on 3.14).
- **Git**.
- **Disk:** ~1 GB free for the dataset, its parquet cache and the prediction cache.
- **Memory:** the full 6.36 M-row frame is held in memory and random forest / XGBoost are trained on ~4.45 M rows; plan for 16 GB of RAM for levels 3 and 4.
- **A Kaggle account** (free) for the dataset, or a browser to download it by hand.
- **Docker** — optional, only for the containerised prototype.

The committed results were produced on Windows 11. All commands below are given for both Windows (PowerShell or Git Bash) and macOS/Linux; run every command **from the repository root**.

### Step 1 — Clone and install

> **Clone the `experiment-suite` branch.** At the time of writing the default branch (`main`) on GitHub holds only this README's predecessor, the licence and `.gitignore`; all code, notebooks and results are on `experiment-suite`.

```bash
git clone -b experiment-suite https://github.com/CodeHermez/momo-fraud-supervised-ml.git
cd momo-fraud-supervised-ml
```

Create a virtual environment and install the pinned research environment, then the library itself in editable mode:

```bash
# Windows
python -m venv .venv
.venv\Scripts\activate
# macOS / Linux
python3 -m venv .venv
source .venv/bin/activate

# both
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m pip install -e .
```

`requirements.txt` pins every package the study used (numpy 2.4.4, pandas 3.0.2, scikit-learn 1.8.0, xgboost 3.4.0, lightgbm 4.7.0, imbalanced-learn 0.14.2, shap 0.52.0, …) plus JupyterLab, the Kaggle client and Streamlit. Do not upgrade them: `results/experiment_environment.json` records the exact versions behind every committed number, and a moved dependency is the first thing to rule out if something fails to reproduce.

The editable install (`pip install -e .`) is what makes `import momo_fraud` work from the prototype and the scripts. The notebooks patch `sys.path` themselves, but nothing else does.

> The rest of this guide assumes the virtual environment is **active**, so `python` means the venv's interpreter.

### Step 2 — Get the dataset

The study uses Kaggle's [`ealaxi/paysim1`](https://www.kaggle.com/datasets/ealaxi/paysim1), file `PS_20174392719_1491204439457_log.csv`, placed at:

```
data/raw/PS_20174392719_1491204439457_log.csv
```

**Option A — let notebook 00 download it.** Create a Kaggle API token (*kaggle.com → Settings → API → Create New Token*) and save it as either

- `~/.kaggle/access_token` — the bare `KGAT_…` token on one line (what Kaggle currently issues), or
- `~/.kaggle/kaggle.json` — the older `{"username": …, "key": …}` file.

On Windows `~` is `C:\Users\<you>`. Then run notebook 00 (see [Level 3](#level-3--re-run-the-notebooks-and-repairs)), or just its download:

```bash
jupyter nbconvert --to notebook --execute --inplace notebooks/00_data_acquisition.ipynb
```

**Option B — download by hand.** Download the dataset zip from the Kaggle page, and unzip the CSV into `data/raw/` (create the folder).

**Either way, check you have the canonical file.** Notebook 00 refuses to proceed on anything else, and every result in `results/` is tied to this checksum:

```
sha256  16910f90577b0d981bf8ff289714510bb89bc71bff7d3f220f024e287e4eea6b
rows    6,362,620   (8,213 fraud, prevalence 0.1291%)
```

```bash
# macOS / Linux / Git Bash
sha256sum data/raw/PS_20174392719_1491204439457_log.csv
# PowerShell
Get-FileHash data\raw\PS_20174392719_1491204439457_log.csv -Algorithm SHA256
```

The first time any code loads the CSV it writes `data/processed/paysim.parquet` as a faster cache; later loads use that.

### Level 2 — Run the prototype

The prototype is a Streamlit app with seven pages: score a transaction, build a table, batch upload, threshold and risk, test-set explorer, experiment results, model card. All inference goes through `src/momo_fraud/predict.py`, the same code path the experiments use.

**Minimum — no dataset needed.** Five of the seven pages work from what is committed (`artifacts/`, `results/`, `figures/`):

```bash
streamlit run prototype/app.py
```

It opens on <http://localhost:8501>. `prototype/assets/sample_transactions.csv` is a valid 200-row file for the *Batch upload* page.

**All seven pages.** Two pages need files derived from the dataset:

| Page | Needs | Built by |
| --- | --- | --- |
| 4 · Threshold and risk | `predictions/xgboost__unweighted__test__seed42__no_origin_balance.parquet` | notebook 03 |
| 5 · Test set explorer | `prototype/data/demo_sample.parquet` | `prototype/scripts/build_demo_sample.py` |

Pages degrade with an explanation when a file is missing; none of them traceback. To build both, with the dataset in place ([Step 2](#step-2--get-the-dataset)):

```bash
jupyter nbconvert --to notebook --execute --inplace --ExecutePreprocessor.timeout=-1 notebooks/03_baselines.ipynb
python prototype/scripts/build_demo_sample.py      # a couple of minutes; ~2 MB output
streamlit run prototype/app.py
```

`build_demo_sample.py` asserts that the prediction file and the rebuilt seed-42 test split line up row for row, so a misaligned explorer fails loudly instead of mislabelling transactions.

**Docker.** Build both derived files above first. The `Dockerfile` copies the prediction file in by name, so the build fails without it; without the demo sample the build succeeds but page 5 is empty in the image.

```bash
docker build -t momo-fraud-demo .                  # about 12 minutes cold
docker run --rm -p 8501:8501 momo-fraud-demo
```

Build from the repository root. The image installs `prototype/requirements.txt` (inference-only, same pins, CPU-only XGBoost) rather than the root file, and does not contain the raw CSV. To check the image rather than trust it:

```bash
docker run -d --name momo-demo -p 8501:8501 momo-fraud-demo
docker exec momo-demo python -m pytest prototype/tests -q
docker stop momo-demo && docker rm momo-demo
```

`prototype/README.md` documents the pages, the input contract and the two-models caveat (the bundle in `artifacts/` is refit on train + validation; every reported metric comes from the train-only model) in full.

### Level 4 — Re-run the experiments (E3, E2, E4, E6)

Four experiments ran against the frozen baseline (`results/frozen_experimental_baseline.json`, baseline id `b2e6f624`). Each runner has `--smoke` (one cell, independent check), `--run` (the matrix), `--aggregate` and `--qc`. They need the dataset, and they must run in this order because each feeds the next:

```
E3  ──fits 220 models, caches predictions/*__s{split}.parquet──┐
 └─> E2  reuses E3's unweighted and R=773.70 cells, fits 260 more
      └─> E4  reads E2_runs.csv + E3's cached test vectors (no fitting)
      └─> E6  reads E2_runs.csv + cached val/test vectors (no fitting)
```

> **Move the committed cells aside before you run anything in this level.**
>
> E2 and E3 write one JSON per completed cell into `results/E2_cells/` and `results/E3_cells/`, and skip any cell already there. Those folders are committed, so on a clone `--run` prints `E3 matrix: 220 planned, 220 already complete, 0 to run`, fits nothing, and never builds the `predictions/` cache that E4 and E6 read. Moving them aside (rather than deleting them) gives the runners an empty folder to fill and keeps the committed cells on disk to compare against afterwards:
>
> ```bash
> # macOS / Linux / Git Bash
> mv results/E3_cells results/E3_cells.committed
> mv results/E2_cells results/E2_cells.committed
> ```
>
> ```powershell
> # PowerShell
> Rename-Item results\E3_cells E3_cells.committed
> Rename-Item results\E2_cells E2_cells.committed
> ```
>
> Nothing reads the `*.committed` folders except the comparison script below. E6 needs no such step: it recomputes every cell on each `--run`.

Then, in this order:

```bash
# E3 — multi-seed x multi-split robustness: 4 learners x 4 variants x 4 split seeds x 4 model seeds
python scripts/experiments/E3_multiseed_multisplit.py --smoke
python scripts/experiments/E3_multiseed_multisplit.py --run
python scripts/experiments/E3_multiseed_multisplit.py --aggregate --qc

# E2 — training cost-ratio sweep: six R_train values, class weighting only
python scripts/experiments/E2_training_cost_sweep.py --smoke
python scripts/experiments/E2_training_cost_sweep.py --run
python scripts/experiments/E2_training_cost_sweep.py --aggregate --qc

# E4 — prevalence-only manipulation of the evaluation set (cache-only)
python scripts/experiments/E4_prevalence_manipulation.py --smoke
python scripts/experiments/E4_prevalence_manipulation.py --run --aggregate --qc

# E6 — threshold-rule divergence across R_eval (cache-only)
python scripts/experiments/E6_threshold_divergence.py --smoke
python scripts/experiments/E6_threshold_divergence.py --run --aggregate --qc
python scripts/experiments/E6_figure.py
```

E3 and E2 are the expensive ones — 480 model fits on ~4.45 M training rows, including random forests and XGBoost — so expect hours, not minutes. Both are resumable: interrupt them and re-run `--run`, and only unfinished cells are fitted. A crashed cell leaves no file. The smoke cell is kept as a completed cell, so `--run` after `--smoke` fits one fewer.

**Only aggregate a finished matrix.** `--aggregate` summarises whatever cells are in the folder and does not warn if some are missing. Before aggregating, re-run `--run` once more and check it prints `220 planned, 220 already complete, 0 to run` for E3 (`260 … 260 … 0` for E2).

Each experiment's `--qc` writes `results/E*_qc.json` with a PASS/FAIL verdict, and checks among other things that the frozen baseline artifacts were not modified.

### Comparing your run with the committed results

`git diff` alone is misleading here. Every re-run cell records its own timestamp, commit SHA and fit time, so a diff marks every cell as changed even when no number moved. `scripts/experiments/compare_with_committed.py` compares everything *except* those fields, and exits non-zero if any value differs:

```bash
# the refitted cells, against the copies moved aside above
python scripts/experiments/compare_with_committed.py E3 E2

# E6's cells, against git HEAD (there is no moved-aside copy)
python scripts/experiments/compare_with_committed.py E6

# the aggregated tables, each against its committed version in git HEAD
python scripts/experiments/compare_with_committed.py \
    --csv results/E3_runs.csv --csv results/E2_runs.csv \
    --csv results/E4_runs.csv.gz --csv results/E6_paired_by_level.csv
```

A reproduced cell reads `1 identical, 0 differ`; a differing one is listed with the column and the largest absolute gap. It can be run part-way through a re-run: cells not yet refitted are simply not compared.

For the notebook and repair outputs of Level 3, which carry no per-run fields, `git` is enough:

```bash
git status
git diff --stat -- results figures
git diff -- results/04_h1_verdict_v2.csv        # inspect one file
```

What should and should not move:

- **Should match exactly:** every metric, threshold and confusion count, and the cached probability vectors themselves. Run on the canonical CSV with the pinned packages, the E3 smoke cell (`xgboost / rus / split 123 / model 456`) and the E2 smoke cell (`random_forest / R_train 50 / split 456 / model 789`) both reproduce their committed cells exactly, with bit-identical validation and test scores. Seeds are fixed: `42` for the frozen baseline, and split and model seeds `42, 123, 456, 789` in E2/E3.
- **Will differ:** `fit_seconds`, `cell_seconds`, `git_sha`, `git_dirty`, `timestamp_utc` and the `*_provenance.json` files (they record *your* run), plus PDF metadata.
- **If a number differs:** compare your `pip freeze` against `results/experiment_environment.json` first, then the dataset checksum, then the platform. The committed results come from one Windows 11 machine, and multithreaded tree learners can differ in the last decimal places on another CPU or operating system.

**Putting the committed record back.** The re-run has created new `results/E2_cells/` and `results/E3_cells/` folders, so delete those before moving the originals back. Otherwise `mv` nests the old folder inside the new one:

```bash
# macOS / Linux / Git Bash
rm -rf results/E3_cells results/E2_cells
mv results/E3_cells.committed results/E3_cells
mv results/E2_cells.committed results/E2_cells
git checkout -- results figures artifacts
git status                                       # should be clean
```

```powershell
# PowerShell
Remove-Item -Recurse -Force results\E3_cells, results\E2_cells
Rename-Item results\E3_cells.committed E3_cells
Rename-Item results\E2_cells.committed E2_cells
git checkout -- results figures artifacts
git status
```

`predictions/` and `data/` are gitignored and stay where they are; delete them if you want the disk space back.

## The study

### The question

Does cost-sensitive learning actually improve fraud detection on severely imbalanced mobile money data, and _which level_ of it does the work: data, algorithm, or decision?

Johnson & Khoshgoftaar (2022) showed on Medicare Part B claims (8,669,497 rows, 0.0456% positive) that class weighting and undersampling **reduce** a learner's discriminative power, and that thresholding alone outperforms both. They asked for replication on other severely imbalanced datasets. PaySim, at 0.129% prevalence, is that dataset, and no prior mobile money study reports any risk analysis at all.

### Findings

**PaySim's fraud is recoverable by three boolean clauses.**

```
type ∈ {TRANSFER, CASH_OUT}  AND  amount == oldbalanceOrg  AND  newbalanceOrig == 0
```

Precision **0.9999**, recall **0.9770**, on all 6,362,620 transactions. Every published machine-learning result we found on this dataset scores _below_ a rule with no parameters and no training. Results on the full feature set therefore measure the simulator, not fraud detection, which is why the experiment runs on an ablated feature set (`notebooks/02`, `notebooks/03`).

This is an in-sample descriptive property of the released dataset, not a held-out detector result. The PaySim paper places fraud generation explicitly outside its scope, so there is no documented generative rule to appeal to.

**Cost-sensitive _training_ does not improve ranking quality; cost-sensitive _thresholding_ reduces risk.**

Across four learners and twelve paired comparisons (class weighting, per-instance severity weighting, and undersampling) **none improved PR-AUC over the unweighted baseline**. All twelve deltas were negative (−0.0159 to −0.5693), every paired bootstrap CI excluding zero at `n_boot = 2000`. Varying the split and the training seed does not change this: **116 of 116** paired comparisons are negative across 4 split seeds × 4 model seeds.

Moving the threshold instead removes **49–62%** of the risk (NER 0.6591 → 0.2499 for logistic regression, 0.3206 → 0.1324 for random forest).

**On end-to-end risk the picture is learner-dependent, and that dependence is itself stable.** Logistic regression and the decision tree benefit from cost-sensitive training in 64 of 64 paired cells; random forest and XGBoost are harmed in 61 of 64. Only the ranking-quality result is uniform. The blunt claim "cost-sensitive learning never helps" is not supported and is explicitly forbidden by the frozen baseline.

**At `R = N_neg/N_pos`, risk-optimal and ROC-optimal thresholds are the same threshold.**

Minimising `FP + R·FN` reduces to maximising `TPR − FPR` at that ratio, provably, for every model. Measured across 104 frozen model cells, the two rules select a **bit-identical** threshold in every one, maximum gap `0.000e+00`. Away from the ratio they diverge, and below it the ROC-optimal threshold can be worse than flagging nothing. This reframes the apparent "statistical versus business threshold" disagreement in the literature as a disagreement between two _cost ratios_.

**`amount` is not the most important feature.**

Once the simulator's origin-balance bookkeeping is removed, transaction **type** dominates (permutation importance 0.701 versus 0.447 for amount). Prior work reporting amount as the top predictor did so with those balance features present. This result is **provisional**: permutation importance is distorted by correlated features and grouped permutation importance has not been run.

### The risk framework

One interpretable knob replaces every currency figure:

> **R**: "missing one fraud is as bad as R false alarms."

All three cost-sensitive levels in the proposal's section 3.3 taxonomy derive from it:

| Level     | Technique       | Derived from R         |
| --------- | --------------- | ---------------------- |
| Data      | undersampling   | `N'_neg = N_neg / R`   |
| Algorithm | class weighting | `scale_pos_weight = R` |
| Decision  | thresholding    | `λ = 1 / (1 + R)`      |

For PaySim `R = N_neg/N_pos = 773.70`, which puts `λ` exactly at the class prior (0.00129), as the theory predicts. Johnson & Khoshgoftaar use the same parameterisation, so the replication is like-for-like at the level of the cost model and not only at the level of the headline claim.

Results are reported as **PR-AUC** (model quality), **Recall@budget** ("if analysts review _k_ transactions a day, what share of fraud is caught?"), and **Normalized Expected Risk**: the proposal's `TotalCost` divided by the do-nothing baseline, so it lands in [0,1] with 1.0 meaning "no better than ignoring the problem". Accuracy is excluded, and the exclusion is enforced in code.

### Audit, repair and freeze

The study audited its own measurement system before drawing conclusions. Twenty findings; sixteen repaired, four deferred with stated reasons. The three that changed conclusions:

- a temporal split that realised **95.6/3.0/1.4** instead of 70/15/15, with test prevalence 1.391% against a true 0.129%;
- rung, best-configuration and learner selection performed on **test** NER;
- confidence-interval overlap used as a significance rule, replaced by a paired stratified bootstrap.

Superseded artifacts are retained, versioned, and indexed by status in `results/experiment_index.json`; nothing was deleted. The configuration was then **frozen** (dataset checksum, feature set, splits, cost ratio, threshold protocol, metrics) and verified by nine consistency checks that read the notebooks and library rather than trusting a declaration (`scripts/freeze/consistency_checks.py`). Unfreezing requires a change-log entry (`results/methodology_change_log.json`); a better score is not a reason.

The condensed record of the audit, the freeze and the experiments is `evidence/audit_and_experiment_summary.pdf`.

### Experiments

Four experiments ran against the frozen baseline: 480 distinct model fits, reported over 792 evaluation cells once cached fits are reused. Each carries a quality-control report (`results/E*_qc.json`) and an independent smoke test (`results/E*_smoke_test.json`), and each states what it does not establish.

| | Question | Scale | Outcome |
| --- | --- | --- | --- |
| **E2** | Does the result hold at other _training_ cost ratios? | 364 cells | Learner ranking XGB > RF > DT > LR, 0 violations in 112 |
| **E3** | Does it survive seeds and splits? | 220 fits | 116/116 negative; NER effect learner-dependent and stably so |
| **E4** | How much of the precision collapse is prevalence alone? | 104 cells | Model and threshold frozen; measured, not suggestive |
| **E6** | Where is the threshold comparison informative at all? | 104 cells | Equivalence exact in 104/104; divergence asymmetric |

Scripts in `scripts/experiments/`; each script's docstring states its design, what is held fixed and why.

### Risk bands and authentication

The dataset carries no authentication, session, device, SIM, PIN, channel or location field, so the study's authentication research question **cannot be answered empirically** and no experiment was manufactured to pretend otherwise. It is resolved instead as a design contribution: the same declared `R` that sets the alerting threshold also sets an authentication escalation ladder, because `band_cutoffs` anchors every boundary on `λ`.

What is measured is the ladder's operational load: **97.04%** of transactions see no additional friction while the two escalated bands, 2.96% of traffic, carry **90.2%** of the fraud (`scripts/report/build_auth_tables.py`, from `results/06_risk_bands.csv`). What is **not** claimed is that any escalation works: no control was tested, and PaySim's fraud is an account-draining signature rather than an authentication compromise. That boundary is enforced in code and asserted by a test.

### Data

PaySim is synthetic. `02_leakage_audit` identifies which features encode the _simulator_ rather than fraud behaviour, and every headline result is produced twice, with and without them.

The supportable claim about the resulting feature set is **reduced simulator artefact exposure**, not "simulator-independent" and not "artefact-free". A test asserts that wording is not overstated.
